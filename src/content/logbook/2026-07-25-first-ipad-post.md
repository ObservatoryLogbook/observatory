I'm testing out various ways of publishing observations from just my iPad. Previously, everything has been done through my Macbook, but I have an upcoming trip, where I will not bring it - so I need to have a mobile workflow. 

This little corner of the internet is current,y set up in a way where I generate entries and test functions, design and architecture on my Macbook, I then commit and push it to a Github repository. From there, Netlify reads and updates the actual website. While I only need to be able to generate entries and add images while on the go, that still needs to be seamless. 

The current options I am testing are: 
- Github.dev: editing in a VS Code environment in the browser, where I directly edit files in the browser. 
- Github.com: similar, but directly in the Github repository. 
- Working copy: a dedicated Danish-developed app for working with and in Github repository. However, for working directly in the repository, a Pro plan is needed. 

I am currently testing out Github.dev, which works just fine. It connects directly to the Github repository without problems. 

![First iPad image](images/2026-07-25-first-ipad-image.jpeg)

In order to upload an image, it seems to be easier to go straight to the Github repository on github.com and adding it there (after copying it through the iOS system and converting it to jpeg-format). 

The biggest drawback of working in github.dev is that autocorrect does not work. I understand that: in a developer environment, autocorrect can be very frustrating, however, as someone who has grown accustomed to work with autocorrect and rely on it for capitalizing letters at the beginning of sentences, it is a bit annoying. At least it will keep the entries short. 

Tomorrow I will test Working copy.
